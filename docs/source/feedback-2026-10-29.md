# 외부 사용 평가 (2026-10-29, Mac 에서 공개 저장소를 읽고 쓴 평가)

> 평가 시점의 공개 상태: GitHub 기본 브랜치 `main` = 61e5f17 (2026-10-27), npm `crewdroid@0.1.0` (2026-10-26). `ai/work` 의 T53·T54·T55 등 134 커밋은 아직 배포 전이었다.

## 좋은 점
- Android Studio 없이 명령 한 줄로 화면 없는 에뮬레이터. 설치·실행·화면·탭·입력·로그를 MCP 도구와 `--json` CLI 로.
- 에이전트가 읽기 좋은 결과: `launch` 의 `crashed`·예외 요약, `logs` 앱 로그만, 설정 명령의 재확인.
- 기기 상태 조절: 권한, 딥링크, Doze, 메모리 압박, 다크 모드, 글자 크기, 위치, 폴드/플립, 기기별 네트워크 끊김·지연.
- 안전장치: adb 는 `emulator-<port>` 에만.
- 고유 기능: 여러 기기 실행 뒤 `judge` 로 서버 데이터의 중복·누락·덮어쓰기 판정.

## 아쉬운 점
- 다중 사용자 시나리오(`run`)는 들어 있는 샘플 앱에서만 돈다. 내 앱용(T55)은 할 일로 남아 있다.
- 자체 벤치마크가 장점과 반대: 접근성 트리 방식이 스크린샷 방식보다 토큰 1.5배, 시간 2.3배. 개선(T53, T54) 진행 전.
- ATD 이미지라 Chrome, 카메라 앱, 런처가 없다. 웹뷰 로그인이나 외부 앱 인텐트 흐름은 막힐 수 있다.
- 며칠 만에 AI 오토파일럿으로 만든 v0.2 단계. 저장소의 비평 문서도 "좋은 아이디어의 작동하는 데모"라고 평가.

## 결론
- 일반 앱 개발 루프에는 쓸 만하나 mobile-mcp + Android Studio 에뮬레이터 조합보다 확실히 낫다고 하기 어렵다. 장점은 가볍게 띄우기와 에이전트가 읽기 좋은 출력.
- 오프라인 동기화·동시성 버그를 잡을 앱이면 고유 가치. 다만 시나리오를 직접 짜야 한다.
- Mac 에서 쓰려면 `setup` 버그를 먼저 고쳐야 한다(버그 내용은 이 평가 앞부분에 있었고 받은 글에는 빠짐).
- 실제로 돌리려면 SDK 약 1.1 GB 와 Android SDK 라이선스 동의가 필요.
