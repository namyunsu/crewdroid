> 오토파일럿이 만들 투두를 세심하게 짜야해

## 정리된 목표 (계획 세션이 Todo 로 쪼갤 것 — 아직 확정 아님)
1. **경량 AVD 위에 얹을 수 있는 기능은 전부.** 기존: 혼합 기종 기동·네트워크 상태·판정·API 동시 요청·오프라인 시나리오. 후보 예: 임의 화면/접이식(T18·T19), 위치·센서·배터리·통화/SMS 흉내, 화면 회전·다크모드·글자 크기·언어, 권한 부여/회수, 딥링크·인텐트, 앱 데이터 초기화·백업, 저장공간 부족·저메모리·백그라운드 제한(Doze) 흉내, 시간대/시계 조작, 스냅샷으로 상태 되돌리기 등. 각 기능은 "경량을 해치지 않는가"를 수치로 확인.
2. **AI 가 잘 찾고 잘 도입하게.** 저장소 자체를 AI 친화적으로: crewdroid 를 MCP 서버로 노출, Claude Code 스킬/플러그인·AGENTS.md·llms.txt, 영문 README(첫 화면에 한 줄 설치·데모 GIF·숫자), npm 배포, GitHub topics, 예제. "AI 에게 노출"이 많아지는 경로(레지스트리·목록 등록)를 조사해 고른다.
3. **안드로이드 앱 특화 스킬로 AI 가 깊게 다룸.** 예: logcat/ANR/크래시 분류, 접근성 트리로 화면 이해, 권한·인텐트·딥링크 다루기, APK 정보(매니페스트·권한·minSdk) 읽기, 성능(프레임·메모리) 측정, WebView/Compose 화면 조작, 오프라인·동시성 버그 재현 레시피. 스킬은 짧고 검증 가능한 명령으로.
4. **목표: GitHub 스타.** 공개 전환은 사람이 결정(지금 비공개). 공개 전에 할 일(라이선스, 영문 문서, 데모, 보안 점검 — 개인 경로·계정·실기기 정보 제거)을 Todo 로.

## 지켜야 할 것 (변경 없음)
- 배리어("동시에 누르기") 없음. 기종이 같다고 가정하지 않음. adb 는 `emulator-<port>` 만.
- 경량화가 최우선: 새 기능은 디스크·RAM·CPU 수치를 해치지 않는지 확인.
- 0.9GB 넘는 다운로드·자원 삭제·공개 전환·npm 배포는 사람 승인.
