# 0006 폴드·플립 접기/펴기 — ATD 에서는 `wm size/density` 바꾸기

- 날짜: 2026-10-26 · 상태: 실측 근거 있음 (T19, API 34 만 실측)
- 결정: `crewdroid fold <serial>` = 커버 화면, `crewdroid unfold <serial>` = 메인 화면. 두 화면은 `profiles/galaxy.json` 의 `fold: { cover, main }` (fold5-cover·fold5-main·flip6-cover·flip7-main·fold8-main). 명령은 기기의 현재 `wm size` 로 짝을 찾아 `wm size` + `wm density` 를 바꾸고 되읽는다. 앱은 진짜 configuration change(새 화면 크기)를 받는다. 베이스 AVD·기동 플래그·`KNOBS` 는 그대로다. MCP 도구 `fold` (`to: cover|main`) 도 같은 함수다.
- 확인: `node scripts/check-fold.mjs` [확인함 `.ai-log/evidence/T19-1.txt`], 실험 기록 [확인함 `.ai-log/evidence/T19-1-foldable-avd.txt`]

## 시도한 것
| 방법 | 결과 | 근거 |
|---|---|---|
| crew 베이스 AVD 클론에서 `adb emu fold` / `unfold` | `KO: Device is not foldable` | [확인함 T19-1-foldable-avd.txt] |
| 같은 클론에서 `adb emu posture 2` | `KO: Failed to set posture` | [확인함] |
| 같은 클론에서 `cmd device_state print-states` | `DEFAULT` 하나뿐 → `state 1` 은 "not supported" | [확인함] |
| 임시 AVD: android-34 google_atd + `avdmanager -d pixel_fold` (`hw.sensor.hinge*`, `hw.displayRegion.0.1` 1080x2092), 콜드 부팅 | 부팅됨(40.6 s). device state 가 CLOSED/HALF_OPENED/OPENED/REAR_DISPLAY_MODE 로 늘고 `adb emu fold` → `OK`, `mCommittedState` 가 CLOSED ↔ OPENED 로 바뀐다 | [확인함] |
| 그 임시 AVD 에서 fold 뒤 앱 화면 | **안 바뀐다.** 바깥 화면은 별도 논리 디스플레이 2(1080x2092)로만 생기고, 앱은 디스플레이 0(2208x1840)에 그대로 있다. `wm size` 도 2208x1840 그대로 → 앱에 configuration change 가 없다 | [확인함 `dumpsys window displays`] |
| `wm size` + `wm density` 바꾸기 (채택) | 앱이 `CONFIG <w>x<h>` 를 찍고 screencap 크기도 바뀐다 (fold5 1812x2176 ↔ 904x2316, flip6 720x748 ↔ 1080x2640) | [확인함 check-fold] |

pixel_fold 쪽이 화면을 못 바꾸는 이유는 ATD 이미지에 device state → 디스플레이 배치 설정(접으면 바깥 화면을 디스플레이 0 으로 옮기는 layout 설정)이 없어서로 본다 [추론: device state 는 바뀌는데 논리 디스플레이 배치가 그대로; 이미지 안 설정 파일은 찾지 않았다]. API 36 에서 같은 실험은 하지 않았다 [모름].

## 진짜 폴더블을 쓰려면 드는 비용
두 번째 베이스 AVD(폴더블 설정) + 그 퀵부트 스냅샷이 API 마다 하나씩 필요하다. 임시 AVD 디렉터리는 콜드 부팅 한 번 뒤 5,049,839,680 바이트(겉보기 크기, 스냅샷 없음) [확인함 `du -sb`]. 그래도 위처럼 ATD 에서는 앱 화면이 바뀌지 않아 얻는 것이 없다. 그래서 두 번째 베이스 AVD 는 만들지 않았고 임시 AVD 는 지웠다.

## 대체 방식이 흉내 내지 않는 것
- 힌지 각도·자세(posture): 반쯤 접기(HALF_OPENED, 테이블톱 모드), 텐트, `WindowLayoutInfo`/`FoldingFeature` (Jetpack WindowManager) 는 앱에 오지 않는다.
- device state 변경(`DeviceStateManager` 콜백), 바깥 화면과 안쪽 화면이 동시에 있는 상태, 듀얼 스크린·리어 디스플레이 모드.
- 실제 기기처럼 접을 때 앱이 커버 화면으로 "이어지는지(continuity)" 설정. `wm size` 는 같은 디스플레이 크기만 바꾼다.
- 커버 화면의 컷아웃 모양(플립 폴더형), 커버 화면 위젯 전용 UI.
- 밀도: flip6 메인 480, flip7·fold8 커버 420 은 근거 없는 추정값이다 (`profiles/galaxy.json` note).

## 앱 쪽 (샘플 앱)
- `Outbox.init` 이 애플리케이션 `ComponentCallbacks` 를 걸어 크기가 바뀔 때마다 `CrewProbe CONFIG <w>x<h>` (최대 창 크기, px) 를 찍는다.
- 액티비티는 `configChanges` 를 선언하지 않아 접고 펼 때 다시 만들어진다(실제 앱에서 상태가 날아가는 흔한 경로를 그대로 둔다). outbox 와 올리던 업로드는 프로세스 쪽 스레드라 이어진다: 느린 망에서 1 MB 사진을 올리는 중에 접어도 서버에 정확히 1행, 앱 줄은 `SYNCED` 한 번 [확인함 check-fold].
- 느린 망(`net slow`) 2 MB 업로드: 접기와 무관했다. API 36 에서 접기 없이도 원래 코드는 120 초 안에 `SYNCED` 가 나지 않았다 (3/3 실패, `RETRY ... Socket closed` 반복) [확인함 check-slow-upload 원래 코드 실행]. 원인은 `http()` 의 10 초 감시자: `write()` 는 커널 송신 버퍼(약 1.4 MB, `ss -tin` 의 notsent)에 들어가면 바로 돌아오고 그 뒤 버퍼가 비는 속도로만 깨어나는데, 상대 수신 창이 6 세그먼트 정도라 실제 속도는 약 230 kbit/s(rwnd_limited 100%, `tc` 의 tbf 는 drop 0)다. 그래서 쓰기 사이가 10 초를 넘어 연결이 끊겼다 (`written=1458176/2097311` 에서 매번 같은 자리 [확인함 임시 로그]). 또 마지막 쓰기 뒤 버퍼 꼬리가 비는 데 약 50 초가 걸려 읽기 제한 20 초도 부족했다. 고침(`http()` 만, slow 숫자는 그대로 1024 kbit·300 ms): 감시자 한도 = 10 초 + 본문 64 KB 당 1 초, 쓰기가 끝나면 감시자를 끄고 `readTimeout` 이 지킨다(1 MB 초과분 12 KB 당 +1 초, 1 MB 이하는 20 초 그대로). 고친 뒤 2 MB 는 73.1~74.6 초에 `SYNCED`, 서버 1행, 접는 경우 포함 4/4 [확인함 `node scripts/check-slow-upload.mjs`]. 쓰기 속도 자체(약 29 KB/s)는 에뮬레이터 수신 창이 정해 `shape()` 로 못 바꾼다 [추론 ss 가 rwnd_limited].
